# FGallery — открытые проблемы и ограничения
Обновлено: **2026-11-06**. История до build45: [архив](history/OPEN_BUGS-through-2026-11-02-build45.md). [Статус](PROJECT_STATUS.md) · [ТЗ](FGallery_TZ_v1.md).

## Принято, не переделывать без регрессии
- **S23 build35:** RAW Samsung DNG / Phase One IIQ / Hasselblad 3FR/FFF, превью, сортировка альбомов по датам файлов, индексация и встроенный апдейтер — работают по отчёту пользователя.
- **S23 build30:** обложки альбомов, восстановление навигации, доступы, сортировка папок назначения и видео — приняты. Последующие сборки не означают автоматическую физическую приёмку.

## P1 — замечания пользователя к build47 (2026-11-03)
- **FG-VIDEO-VISIBILITY:** в сетке останавливать видео, если видимая высота плитки <50%; выбирать следующую подходящую видимую видеоплитку, максимум один активный проигрыватель. Проверить скролл вверх/вниз, частично видимые плитки, уход с экрана, возврат из просмотра и экономию ресурсов. Не менять принятые видеожесты.
- **FG-SETTINGS-BACK:** настройки закрываются Android Back; свайп вниз больше не закрывает панель. Проверить Back при раскрытом пункте «Доступы» и жестовую навигацию.
- **FG-SETTINGS-COMPACT:** уменьшить вертикальные интервалы и визуальный размер переключателей, сохранив удобную область касания (ориентир 48 dp); стремиться уместить свернутые настройки целиком на Samsung S23 без прокрутки, учитывать размер шрифта и системные inset.
- **FG-SETTINGS-PERMISSIONS:** объединить «Фото и видео» и «Доступ ко всем файлам» в один раскрываемый пункт «Доступы» с двумя независимыми статусами и действиями; не изменять фактическую модель разрешений.
- **FG-DUP-ENTRY:** добавить видимый пункт «Поиск дубликатов» в главное меню только одновременно с безопасным рабочим экраном: группы точных/проверенных визуальных совпадений, фильтр папок/носителей, причины выбора оригинала, ручной выбор и явное подтверждение переноса в корзину. Не показывать непроверенные dHash-кандидаты как дубликаты и не удалять автоматически.
- **Приёмка:** JVM-тесты для выбора видео по доле видимости и классификации совпадений, Android16 instrumentation для Back/свайпа/раскрытия доступов/корзины; R8 и физическая проверка S23. Статус: **запрошено, не реализовано и не принято**.

## P1 — новые замечания S23 (2026-11-03; ещё не приняты)
- **FG-VIEW-ROTATE-90:** двухпальцевый жест вращения в полноэкранном просмотре; итоговый угол только 0/90/180/270° (по/против часовой стрелки), не произвольный. Плавный визуальный жест допустим, отпускание фиксирует кратный 90° угол. Совместить с pinch-zoom/pan, сбрасывать при смене файла/выходе, никогда не менять исходник, EXIF и не сохранять результат. Проверить RAW/TIFF/PDF/SVG, вращение в обе стороны, многократные повороты, возврат к другому фото.
- **FG-GRID-VIDEO-VISIBILITY:** прекращать живое видео-превью, если видимая высота плитки становится менее 50%; выбирать следующую подходящую видимую плитку; одновременно не более одного видео, корректная остановка при быстрой прокрутке.
- **FG-SETTINGS-BACK:** открытые настройки закрываются Android Back; свайп вниз не закрывает настройки.
- **FG-SETTINGS-COMPACT:** сократить вертикальные отступы и визуальный размер тумблеров, сохранив доступные области нажатия; уместить обычные настройки на экране Samsung S23 без прокрутки.
- **FG-SETTINGS-PERMISSIONS:** один сворачиваемый пункт «Доступы», внутри отдельные статусы и настройки «Фото и видео» и «Все файлы».
- **FG-DUP-ENTRY:** видимый пункт «Поиск дубликатов» в главном меню только вместе с безопасным рабочим экраном: точные/resize/crop, выбор папок, причины выбора оригинала, явное подтверждение корзины, без автоматического удаления и ложных RAW+JPEG/цветокоррекции/ретуши/серии.

## P1 — Stage5
- **FG-INDEX-SAF-DELTA:** полноценная инкрементальная сверка SAF/USB по папкам и MediaStore; сравнение full-vs-delta, корректность при FAT/exFAT с грубым mtime, при отключении/подключении носителя и перезаписи файла под тем же именем. USB/SD тесты пользователь отложил.
- **FG-INDEX-MUTATIONS:** все успешные move/rename/delete/restore/crop должны атомарно обновлять Room, сохранять незатронутые записи и корректно восстанавливать каталог после частичных операций. Существующие фиксы удаления/корзины и отмены сканирования сохранять.
- **FG-SAF-METADATA:** build46 сохраняет обогащённые метаданные неизменённого SAF URI при очередном обходе; Android16 CI пройден, физическая проверка S23 впереди. Не переиспользовать при изменении версии файла.
- **FG-INDEX-ROOM-DELTA:** build47 устраняет повторные REPLACE неизменённых Room-строк с сохранёнными хешами; JVM/Android16 CI пройден, физическая проверка S23 впереди.
- **FG-CRASH:** ранее было одно неповторённое падение на S23, журнал отсутствует; причину не объявлять устранённой.

## P1 — Stage6
- **FG-DUP-EXACT:** SHA-256-копии уже индексируются в фоне, но нужен безопасный UI с группировкой и явным подтверждением. Никаких автоматических удалений.
- **FG-DUP-VISUAL:** 48×48 dHash/RGB — только кандидаты. Нужны проверка оригинальных пикселей для resize/crop, исключение RAW+JPEG пары, цветокоррекции, ретуши, кадров серии и подбор порогов на пользовательском тестовом наборе. Даже совпадение превью не разрешает удаление.
- **FG-DUP-KEEP:** ранжирование оригинала учитывает формат/разрешение/размер/время/камеру, но JPEG quantization и полнота EXIF ещё не реализованы; объяснять пользователю, почему файл предпочтителен.

- **FG-VIDEO-AVI-M4V (открыто):** пользователь подтвердил отсутствие просмотра AVI и M4V на S23. В рабочей ветке внесены изменения выборки MediaStore/SAF и нормализации MIME для M4V, сообщения об ошибках плеера и Android16-тесты MediaExtractor/Media3 на MP4-образце с расширением `.m4v` (коммиты до `8fa2d41279224fa467204210f6d802225dd5c67a`).
- **CI подтверждён:** [integration QA run #42220033989](https://github.com/Mister-Mikhail/FGallery/actions/runs/42220033989) завершился `success` для `8fa2d41279224fa467204210f6d802225dd5c67a`: `r8-build` и `r8-device-tests` успешны; `publish-qa` пропущен. Отдельный workflow `Android CI` пропущен по условиям запуска и не является провалом интеграционного CI.
- **Не считать исправленным:** тест M4V с переименованным MP4 не доказывает работу произвольных M4V, реальный S23 не проверен; для AVI нет доказанной поддержки demux/decode (включая DivX/Xvid/MJPEG и разные аудиокодеки). Требуются реальные AVI/M4V образцы с разными контейнерами/кодеками, проверка сеточного превью и полного просмотра на Android16, а также явное сообщение о неподдерживаемом кодеке/контейнере без чёрного экрана.
- **Выпуск:** новый APK после build48 не опубликован; следующий QA — только после проверки соответствующих сценариев и зелёного CI, с новым versionCode, прежней тестовой подписью и SHA-256. Stable и merge PR #15 запрещены.

## Внешнее открытие файлов — код 2026-11-06, ещё не проверен
- **FG-EXTERNAL-VIEW:** зарегистрированы ACTION_VIEW для content:// и file:// с MIME image/*, video/* и рядом document/RAW MIME; MainActivity открывает полученный URI в просмотрщике, даже если файл отсутствует в каталоге. Коммиты `16aaff916`, `55489b3b`. Требуется Android16 CI и тест из Samsung «Мои файлы»/другого проводника: AVI/M4V/AVIF/DNG/IIQ/PDF/SVG; при неверном MIME `application/octet-stream` системный chooser может не показывать приложение — нужна отдельная совместимая обработка, не захватывая все неизвестные типы. Проверить SAF URI grants, смену файла и отсутствие регрессий в навигации. Это **не подтверждение декодирования AVI**.
- **FG-SHARE-MULTI:** кнопка «Поделиться» для выделения и ACTION_SEND_MULTIPLE в коде (`8375dccc`, `75807681`); требуется JVM/Android16 тест одного и нескольких URI, доступности для внешнего получателя и проверки разных типов файлов.

## AVI FOURCC — дополнительная диагностика 2026-11-07
- Коммиты `a93d85f4`, `54aeb7bf`: если `strh.fccHandler` пуст, анализатор AVI теперь берёт `BITMAPINFOHEADER.biCompression` из `strf` только для видеопотока. JVM-тесты охватывают MJPG fallback и защиту от ложного распознавания аудиопотока. Это диагностическая функция, **не программный AVI-декодер**.
- Для коммита `54aeb7bf` пока нет подтверждённого полного R8/JVM/Android16 CI и опубликованного APK. Не считать AVI/MJPEG воспроизводимым до реального декодирования и проверки на устройстве. По уточнению пользователя M4V в другом образце открылся: универсальный дефект M4V не подтверждён, регрессионные тесты оставить.
